Ce que sont ces tests, et comment les lire

Ce ne sont pas des tests unitaires : ce sont des scripts de vérification de bout en bout. Chaque module expose une fonction run() qu'on lance à la main sur un site Frappe vivant. Le script crée ses propres données (animaux, salariés, factures de test), déroule un scénario réel — de vraies écritures comptables, de vraies factures ERPNext — puis compte ses assertions avec _check(condition, message). À la fin il affiche N/N. Les « 206 tests » sont donc 206 assertions vérifiées, et un crash compte comme un échec.

# Lancer un module (exemple)
bench --site <site> execute hmd_agro.hmd_agro.tests.test_personnel.run
# → affiche le détail de chaque assertion puis {"pass": 28, "fail": 0}

Prérequis : un site bench migré (bench migrate) avec le socle comptable installé (setup_socle_comptable et suivants — l'ordre complet est dans livraison_finance.md). Sans site bench, rien ne tourne : il n'y a pas d'exécution en CI pour l'instant.

Où ils vivent : tous dans hmd_agro/hmd_agro/tests/, un fichier par module, préfixe test_. Les 13 modules finance cohabitent avec une vingtaine de modules troupeau/rapports plus anciens qui ne font pas partie du décompte des 206.

⚠ Site de test uniquement

Certains nettoyages de fin de test suppriment des données par marqueur ou sans filtre (bilans lait, écriture de paie du mois courant). Relevé par la review de la PR #1 — ne jamais lancer la suite sur la base réelle de la ferme tant que ce n'est pas corrigé.
